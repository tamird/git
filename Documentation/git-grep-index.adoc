git-grep-index(1)
=================

NAME
----
git-grep-index - Write grep acceleration indexes


SYNOPSIS
--------
[verse]
'git grep-index' [--[no-]progress] [--reachable [<revision>...] [-- [<path>...]]]
'git grep-index' [--[no-]progress] --compute-locale-safety

DESCRIPTION
-----------
Write an incremental content index for blobs registered in the indexes of
all worktrees that share the repository. The index is stored in the common
object directory, so all of those worktrees and concurrent `git grep`
processes share it.

The content index contains Bloom filters for blob trigrams. For supported
searches, linkgit:git-grep[1] uses the filters to avoid reading blobs that
cannot contain the pattern. Blobs not present in the content index are
searched normally. Some case-insensitive regular expressions need an
additional per-blob safety record before their filters can exclude a blob;
new filters include this record. Blobs in older indexes without that record
are searched normally until `--compute-locale-safety` checks them.

By default, blobs are selected from the indexes of all worktrees. With
`--reachable`, blobs are instead selected by a revision walk. If no revision
is given, all refs are walked.

OPTIONS
-------

--progress::
--no-progress::
	Turn progress reporting on or off explicitly. If neither is
	specified, progress is shown if standard error is connected to a
	terminal.

--reachable::
	Index blobs reachable from the given revisions, optionally restricted
	by a pathspec. With a pathspec and no revision, specify `--all`
	explicitly.

--compute-locale-safety::
	Check the blobs in existing content indexes and record which have
	verified content containing only ASCII bytes and no ESC byte.
	Supported case-insensitive basic and extended regular expressions can
	then use these records when the effective collation is C and the
	character encoding is UTF-8. Blobs with other bytes, missing or
	unreadable blobs, and indexes without a valid safety record are searched
	normally. This explicit operation may read and verify every indexed
	blob up to 64 MiB, so its running time and disk reads scale with the
	total size of those blobs. It does not rewrite existing Bloom filters.
